# PEAK 第一批分析與建庫計畫

可執行計畫：[plans/peak-core-v1.json](../plans/peak-core-v1.json)。保存端會驗證並保存這份檔案，依欄位型別、來源類型、具體目標和關聯方向接收待審知識；不是另一份僅供閱讀的分類表。

分析基於 [Wikipedia 的 PEAK 介紹及 Gameplay](https://en.wikipedia.org/wiki/Peak_(video_game))，頁面於 2026-10-21 觀測。它是待核對的二手資料，不等於已驗證的遊戲 build。本文與計畫為分類設計及中文整理；來源歸屬 Wikipedia contributors，文字改寫依 CC BY-SA 4.0 保留歸屬與變更說明。

PEAK 的核心是合作登山求援。玩家要管理體力及負面狀態，使用物品、通過地形並處理隊友救援。建庫因此以玩家會問的問題切分：遊戲是什麼、怎麼組隊、規則如何運作、物件能做什麼、在何處、怎麼完成任務，以及世界觀、外部評價與官方更新。

本批採 13 個類別：介紹、模式、機制、狀態、道具、區域、玩家角色、生物／威脅、攻略、徽章／成就、世界觀、評價、官方更新。玩家 Scout 身分適用角色分類；目前沒有證據支持固定職業及技能樹，因此不建立職業表。網站分類與章節僅是來源定位。

13 個具體目標為 PEAK 概況、合作登山、體力、受傷、繩索卷、岸邊、Scout、Scoutmaster、復活隊友、徽章系統、失事與求援、評價概況及官方更新。完整問題、欄位／單位、優先順序、來源定位及缺口均在 JSON 中。這是有界首批，並非所有道具或所有關卡已列完。

關聯計畫包含：介紹包含模式、模式／道具／攻略使用機制、狀態等影響機制或角色、攻略需要物品、物件位於區域、故事／評價描述對象、成就解鎖對象，以及官方更新影響對象。每一條實際關聯都需精確引文；來源只寫「相關道具」時不猜成具體物品。

介紹、玩法規則與主觀評價分開。評價保存評論者、日期、立場、理由和評分量尺，二手概述不能冒充原評論。官方更新只接受官方證據，Wiki 轉述不能填入該類別。版本、數值和取得限制不明時用明確缺口，不填零或省略欄位。

## 本批實際結果

本機 Chrome 以 `local_chrome_playwright` 方法對已允許的 Wikipedia 來源擷取 7 段介紹／玩法文字，保留原頁網址、頁面日期、授權與檔案雜湊；以 `rendered_text_html` 表示挑選段落的純文字 HTML，沒有冒稱完整網路回應。圖片和第三方評論引文未保存。本文不適用於禁止採集的 wiki.gg 或其他來源。

A 獨立輸出 `ssr.collection.v1`，B 在新的持久 DB 收納 1 份真實原文快照，整理保存 12 條待審知識、26 個有證據欄位與 5 條關聯；20 個欄位仍明列缺漏。一次校正保留歷史後共 13 個修訂。C 查同一 DB，已經新程序／API 逐筆讀回與 Chrome 實際畫面驗證，待使用者親自驗收。

官方更新是尚未保存的第 13 個目標；來源用途限制未解除。這次沒有移轉舊主機的 228 條目 DB，也沒有批准或發布資料。詳細保存與查詢契約見 [knowledge 的遊戲計畫契約](https://github.com/HGPT-StreamSuite/ssr-knowledge/blob/codex/peak-local-collection/docs/game-plan-contract-v1.md)。
