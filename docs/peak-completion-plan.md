# PEAK 徽章、補給與隱藏終章規劃

2026-10-21，沿用原四份不可變計畫，按「徽章目標 → 準備物品 → 實際操作 → 完成結果」補足條目。以遊戲中的用途、效果和任務決定分類；來源分類頁只作盤點依據。

## 條目與欄位

- [peak-challenges-v1](../plans/peak-challenges-v1.json)：87 個新目標，包括剩餘 52 個徽章、33 個相關道具、納迪爾區域與四護符通關攻略。
- [peak-supplies-v1](../plans/peak-supplies-v1.json)：48 個新道具，涵蓋食物、裝備、大廳物品和已停用的活動物品。
- 徽章保存條件、操作提示、獎勵與適用探險；道具保存用途、取得方式、使用步驟與限制。區域和攻略沿用既有欄位定義。
- 四護符、奇異寶石、童軍之譽與納迪爾按使用順序建立關聯；徽章連到確實可用的道具。引用必須支持該關聯，不能只因同頁出現就建立連結。

目前盤點的道具分類有 133 個來源項目；六種西洋棋棋子以共用條目與別名收錄，四種莓蕉皮亦合為一組，兩個中文／英文別名頁沿用既有條目，合計映射為 123 個道具條目。不同食物效果、顏色和有毒辨識保留；停用道具在名稱和取得方式明示歷史狀態。這個分母只描述本次核對的來源清單。

## 原有九個欄位缺口

以既有 ID 和 plan_id 追加修訂，不把舊條目移到新計畫。

- 童軍團長：補反制方法及號角召喚的追逐例外。
- 徽章概覽：補取得條件、與 Steam 成就同步的關係。
- 失事背景：區分玩家的飛機失事與童軍團長日記的船難。
- 評價：以 PC Gamer 原評測補作者、日期、評分和理由，更新評價立場。
- 昏迷：基準倒數秒數仍待可靠資料；不把狀態門檻或模組參數當成原版基準時長。

## 執行與驗收

1. 選取有明確內容的來源摘錄並保存原文、網址、取得方式與引用位置。索引摘錄不標成完整網頁；正文不重複顯示來源評語。
2. A `intake-file`／`bundle` 只產生 `ssr.collection.v1` 檔案。B 登記計畫和來源，以 `ingest-collection` 保存快照，再用 `import-drafts` 保存整理知識。C 繼續查原來的 `knowledge.sqlite3`。
3. 先以 SQLite backup API 備份原庫，在候選副本跑相同保存流程。139 個變更分成 87、48、4 筆三批，符合 v1 每批 100 筆上限。
4. 候選驗證所有舊修訂、未修改的 current revision、來源、引用、關聯和收件紀錄保留；核對新欄位、引文、同計畫關聯、64 個徽章與 123 個道具清單。
5. 寫入原庫後，以新 CLI 程序、同一服務 API 和實際 Chrome 頁面逐筆讀回。再操作分類、分頁、搜尋、關聯與重新讀取，確認查詢沒有改變 DB。
6. 重送 139 個草稿應全部 unchanged，不增加修訂。保存為 pending_review，與使用者批准發布分開。

v1 每份計畫最多 100 個目標，且關聯兩端必須在同一計畫。新批次沿用這個契約；跨舊計畫的相關內容仍可按名稱搜尋，不為湊連結而改變舊計畫。

真實來源檔、完整編輯草稿、交接檔案、DB、備份與逐筆驗證留在 checkout 外。本輪只處理本機，家裡資料不在執行範圍內。

## 本機實際結果

同一 DB 已由 109／122 增為 **244 條目／261 修訂**，含 64 個逐項徽章、123 個道具；984 個已存欄位、145 條目前關聯，9 個缺欄補 8 個。原 122 個修訂與舊來源／引用／關聯完整保留。139 個草稿及 151 個來源包重送全部 unchanged；全部 244 筆以新 CLI、API 與安裝版 Chrome 頁面逐筆讀回，代表截圖已檢視。collector 52 項、knowledge 140 項測試通過。詳見[保存端驗收紀錄](https://github.com/HGPT-StreamSuite/ssr-knowledge/blob/codex/peak-local-collection/docs/peak-completion-acceptance.md)。
